## 3. 关键实现要点

### P1-7 会话与账户生命周期

- 访问令牌此前只携带随机 `session_id` 却从不落库，登出 / 吊销无从实现。
  改为 `SessionService` 落库 + 逐请求校验，`AuthMiddleware` 与
  `StreamAuthMiddleware` 在签名校验后追加会话校验。
- 新增 `POST /users/logout`（吊销当前）与 `POST /users/logout-all`（吊销其他设备）；
  改密后自动吊销其他设备会话。
- `DeleteUser` 改为事务内级联：会话物理删除、评论软删除、视频标记 `deleted` 并软删除、
  写入删除台账、最后软删除用户。

### P1-11 字段扩展（拆三批推进）

- **11a**：`User.Email/Bio`，注册与资料更新共用 `ValidateEmail`/`ValidateBio`，
  邮箱占用返回 409。
- **11b**：`Video.Description/CoverPath/ViewCount`；转码成功后用 ffprobe 取时长、
  ffmpeg 抽帧生成封面（失败只告警，不影响任务状态）；新增公开封面接口
  `GET /videos/:video_id/cover`（`<img>` 无法携带 Authorization 头）。
- **11c**：新增 `video_likes` 表（`(user_id, video_uuid)` 唯一），关系与冗余计数
  `videos.like_count` 同事务更新，点赞/取消均幂等。

  改为 `limiterEntry{limiter, lastSeen}` + 每 5 分钟回收空闲超 10 分钟的条目，
  并上报 `rate_limiter_entries`。

## 附录：2026-09-30 仓库损坏与修复记录

09-27 的文档提交在执行过程中被中断，`.git` 因此停在「ref 已更新、对象未写完」的中间态：

- `refs/heads/master` 指向新提交 `60ba36ff…`，但该提交对象及其 tree / blob 只写了 **0 字节**；
- `.git/logs/HEAD` 与 `.git/logs/refs/heads/master` 尾部被追加了 189 字节 NUL；
- 索引的 cache-tree 扩展仍指向已损坏的对象，`git status` 直接报
  `fatal: loose object … is corrupt`。

修复步骤（先把 `refs/heads/master` 与两处 reflog 备份到 `/tmp/gitrepair-<时间戳>/`）：

1. 用 reflog 定位最后一个完好提交 `8d5db891ad977597135014321a4ebed6385ba8e5`（P2-3），
   确认其对象类型为 `commit`；
2. 用 `git rev-list --objects 8d5db891…` 校验 6 个 0 字节对象**均不属于既有历史**
   （历史侧 13998 个对象全部可枚举），确认它们是本次中断产生的垃圾对象；
3. 将 `refs/heads/master` 写回 `8d5db891…`，两处 reflog 截断到最后一个换行符；
4. 删除 6 个 0 字节对象；
5. `git reset -q && git add -A` 重建索引（丢弃指向损坏对象的 cache-tree），重新提交文档。

**校验结果**：`git fsck` 干净（仅剩一个既有的 dangling tag `pre-rebase-fix`，
是拆分提交时的临时安全点对象，无 ref 引用，与本事件无关）；`git log` 20 个提交，
工作区干净，文档与代码内容零丢失。

**经验**：提交被中断会留下「ref 已更新但对象未写完」的中间态，此时不要执行
`git gc` 或删除 `.git`；先用 reflog 定位最后一个完好提交，并确认损坏对象不被
既有历史引用，再改写 ref 并重建索引。
