# 2026-10-20 前端性能与推荐系统迭代

## 1. 目标

- 分析 `frontend-new` 首屏资源与播放器加载路径，减少首页无关代码。
- 后端增加可落地、可解释、无额外模型服务依赖的推荐系统。
- 首页与详情页接入推荐结果，保留匿名热门与冷启动回退。

## 2. 前端分析结论

1. 路由此前全部静态导入，首页会下载详情页、登录页、上传页等未访问页面代码。
2. `VideoDetail.vue` 静态导入播放器，导致 `hls.js` 被首页入口依赖链带走。
3. `vendor/client` 手工分块在路由懒加载后形成循环初始化，生产构建出现
   `TypeError: e is not a function`，页面无法挂载。
4. 首页与列表页重复维护视频卡片与封面错误回退逻辑。

## 3. 已实施改动

### 前端

- 首页保留静态入口；`Videos`、`VideoDetail`、`Watch`、`Login`、`Register`、
  `Profile`、`Upload` 改为路由级动态导入。
- `VideoDetail` 使用 `defineAsyncComponent` 延迟加载播放器，HLS 引擎随详情播放器 chunk 加载。
- 移除 `vendor` 手工分块，仅显式拆出 `hls-js`；修复共享依赖循环。
- 新增 `VideoCard.vue`，统一首页与列表页的封面、时长、播放量、作者和推荐理由展示；
  封面使用 320w/720w `srcset` 与 `loading=lazy`。
- 首页新增“热门推荐 / 为你推荐”区块；匿名走热门，登录后按个性化结果切换标题。
- 详情页评论与相关推荐并行加载，侧栏展示封面和推荐理由。

### 后端

- 新增迁移 `0005_create_video_views`：每个用户对每个视频保留一条最近观看记录，
  `updated_at` 表示最近观看时间；up/down 成对。
- `GET /api/v1/recommendations?limit=12&exclude_ids=...`：
  - 无登录或冷启动：按播放量、点赞、新鲜度排序；
  - 登录：最近 100 个观看视频作为种子，统计共同观看用户，再补充候选；
  - 排序分数：协同观看人数、播放量、点赞量与 7 天新鲜度；
  - 返回 `mode=personalized|popular` 和每条视频的 `recommendation_reason`。
- `GET /api/v1/videos/:video_id/related` 复用推荐服务，排除当前视频、已观看视频和本人视频。
- 新增 `OptionalAuthMiddleware`：公开推荐接口有效令牌走个性化，无令牌/失效令牌匿名回退。
- 详情成功访问时幂等记录观看；账号删除、视频删除同步清理观看记录，避免孤儿数据。
- `migrate check` 已覆盖 `VideoView`，本地迁移验证 up → down → up。

## 4. 回退流程

- 前端路由与播放器：可恢复 `backup/videojs-player` 播放器分支；路由改动仅为 component 映射。
- 推荐接口：`mode=popular` 即完整匿名回退，不依赖观看历史。
- 数据库：`migrations/0005_create_video_views.down.sql` 可删除观看行为表；
  接口代码回滚到上一提交即可恢复原同作者相关视频逻辑。

## 6. 下一轮方向

1. 增加推荐曝光、点击、完播指标，评估 CTR / 完播率，而不是只看离线排序。
2. 将共同观看聚合按时间窗口与衰减系数计算；数据量增大后迁移到离线任务或 Redis 预计算。
3. 增加可选 `reason` 策略与 A/B 实验开关，对比热门、协同、内容标签三种来源。
4. 补充内容特征（标题/简介分词、作者、时长）解决新视频冷启动。
5. 前端继续评估 Bootstrap CSS 按需加载；当前主要瓶颈已从 ~575 KB HLS 首屏依赖
   转移为全局 Bootstrap 样式约 312 KB（gzip 45 KB）。
